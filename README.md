# MINIMUM DUNGEON

## ゲームの概要

Pythonで制作した、ターミナル上で動作するターン制のダンジョン探索ゲームです。

プレイヤーはランダムに生成されたダンジョンを探索し、モンスターとの戦闘や回復薬によるHPの回復を行いながら、出口を目指します。全3ステージのダンジョンを攻略することでゲームクリアとなります。

ダンジョンの自動生成や、モンスターの種類ごとに異なる行動AIを実装することで、プレイするたびに異なる探索や戦闘を楽しめるようにしました。

## 動作環境

- OS： Windows
- Python：3.12.10
- 必要なライブラリ:追加ライブラリ不要
- 推奨実行環境:Visual Studio Codeの統合ターミナルなど、ANSIカラーに対応したターミナル

## インストール方法

1. Pythonをインストールする。
2. 本リポジトリをクローン、またはZIPファイルとしてダウンロードして展開する。
3. ターミナルでプロジェクトのフォルダを開く。

Pythonの標準ライブラリのみを使用しているため、追加のライブラリをインストールする必要はありません。

## 起動方法

プロジェクトのフォルダ内で、以下のコマンドを実行してください。

'''bash
python roguelike.py
'''

## 操作方法

- W： 上方向への移動・攻撃
- S： 下方向への移動・攻撃
- A： 左方向への移動・攻撃
- D： 右方向への移動・攻撃
- .： その場で待機
- Q：ゲーム終了

キーを入力し、Enterキーを押すことで操作を実行します。

## 画面上の記号

- `@`：プレイヤー（シアン）
- `#`：壁（グレー）
- `S`：スライム（緑）
- `G`：ゴブリン（オレンジ）
- `O`：オーク（赤）
- `!`：回復薬（黄色）
- `>`：出口（青）

空白部分は移動可能な通路を表しています。

## ゲームのルール

- プレイヤーの初期HP・最大HPは18です。

- プレイヤーが移動・攻撃・待機を行うと、1ターン経過します。

- モンスターがいる方向へ移動しようとすると、モンスターに3ダメージを与えます。

- プレイヤーの行動後、モンスターも移動または攻撃を行います。

- 回復薬を取得すると、HPが最大5回復します。ただし、最大HPを超えて回復することはありません。

- 各ステージには、モンスターが5体、回復薬が4個配置されます。

- 出口に到達すると次のステージへ進みます。

- 全3ステージを攻略するとゲームクリアとなります。

- プレイヤーのHPが0以下になるとゲームオーバーとなります。

## 追加・改良した機能

### 改良機能01：ダンジョンの自動生成

元のゲームでは固定されたマップを使用していましたが、深さ優先探索（DFS：Depth-First Search）による穴掘り法を用いて、ダンジョンを自動生成する機能を実装しました。

すべてのマスを壁として初期化し、ランダムに選択した開始地点から通路を掘り進めます。行き止まりに到達した場合は、スタックを利用してバックトラックを行い、探索を継続します。

現在のマップサイズは横21マス、縦15マスです。

プレイヤー、出口、モンスター、回復薬の配置もランダムにすることで、プレイするたびに異なるダンジョンを探索できるようにしました。

### 改良機能02：複数ステージの実装

元のゲームでは出口に到達するとゲーム終了となっていましたが、複数のステージを攻略する仕組みを実装しました。

出口に到達すると、新しいダンジョンを生成して次のステージへ進みます。

ステージを移動する際は、プレイヤーのHP・最大HP・累計ターン数を引き継ぎます。また、ステージごとの滞在ターン数を管理する処理を追加しました。

現在は全3ステージを攻略することでゲームクリアとなります。

### 改良機能03：モンスターの種類とステータスの追加

元のゲームでは1種類だったモンスターを、3種類に増やしました。

モンスターごとにHP、攻撃力、表示記号、行動AIなどの設定を持たせることで、戦闘や探索に変化を加えました。

| モンスター | 記号 | HP | 攻撃力 |
|---|---|---:|---:|
| スライム | `S` | 3 | 1 |
| ゴブリン | `G` | 5 | 2 |
| オーク | `O` | 8 | 3 |

また、モンスターの初期配置数を3体から5体に変更しました。

### 改良機能04：ゲーム画面の色分け

ANSIエスケープシーケンスを使用し、ターミナル上に表示されるプレイヤー、モンスター、回復薬、出口、壁を色分けしました。

モンスターの種類ごとに異なる色を設定することで、各モンスターを識別しやすくしています。

また、描画処理をrenderer.pyに分離し、ゲームの内部処理に影響を与えずに表示方法を変更できるようにしました。

### 改良機能05：モンスターごとの行動AI

すべてのモンスターがランダムに移動していた元のゲームから、モンスターの種類ごとに異なる行動を行うように改良しました。

スライム：ランダム移動

移動可能な座標と現在位置の中から、ランダムに次の移動先を選択します。

ゴブリン：マンハッタン距離と貪欲法による追跡

マンハッタン距離を使用して、プレイヤーとの距離を計算します。

プレイヤーが5マス以内にいる場合、移動可能な座標の中からプレイヤーとの距離が最も小さくなる座標を選択します。

感知範囲外ではランダムに移動し、感知範囲内でプレイヤーに近づける座標が存在しない場合は、その場で待機します。

オーク：幅優先探索による追跡

幅優先探索（BFS：Breadth-First Search）を使用して、プレイヤーまでの最短経路を探索します。

Pythonの標準ライブラリであるcollectionsのdequeを使用して探索用のキューを管理し、集合を利用して同じ座標の重複探索を防いでいます。

最短経路が見つかった場合は、その経路上の最初の座標へ移動します。

ゴブリンとは異なり、壁を迂回してプレイヤーを追跡することができます。ただし、他のモンスターなどによって経路が塞がれている場合は、その場で待機します。

これらの行動AIを実装することで、モンスターの種類によって異なる戦略が必要になるようにしました。

## 既知の問題・制限事項

- 現在は開発途中のため、以下の機能の追加や調整を予定しています。

- モンスターのリスポーン機能は未実装です。

- 一定ターン経過後に出現する特殊モンスター「死神」は、設定データのみ定義しており、出現処理は未実装です。

- 現在はすべてのステージでマップサイズ、モンスターの初期配置数、回復薬の配置数が共通となっています。

- ステージごとの難易度調整やゲームバランスの調整は今後行う予定です。

- ゴブリンの感知処理では壁を考慮していないため、壁越しにプレイヤーを感知する場合があります。

- ターミナルの種類や設定によっては、色や文字の表示が異なる場合があります。
